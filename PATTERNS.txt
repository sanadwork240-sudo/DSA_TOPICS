pattern 1
For Maximum Depth, Balanced Binary Tree, and Diameter of Binary Tree, the common intuition is: a node can solve its own problem only after it gets the required information from its left and right subtrees. So for every node, we recursively go to the left child and ask, “What information can you give me?”, then do the same for the right child, and finally combine both answers at the current node. The important part is deciding what the recursive function should return. For maximum depth and diameter, the children return their heights; for the balanced-tree problem, they return their height or -1 to signal that the subtree is already unbalanced. Once the current node gets lh and rh, it uses them to solve its own problem—for example, 1 + max(lh,rh) for height, abs(lh-rh) > 1 for balance, and lh + rh for diameter. This is essentially bottom-up/postorder thinking: solve left → solve right → combine at current node → return useful information to the parent.

Brute force vs optimized intuition

In the brute-force approach, you solve the problem for every node separately. For example, for diameter, at each node you calculate the left height and right height, calculate the diameter through that node, and then recursively repeat this for its children. The problem is that height calculations are repeated—when you calculate the height of a subtree for its parent, you may calculate the same subtree's height again when processing that subtree itself. The optimized approach asks: “Since I am already calculating the height, can I use that same calculation to solve the other part of the problem too?” This allows us to calculate the height and diameter together in one traversal. Similarly, for the balanced-tree problem, instead of repeatedly calculating heights, we return -1 as soon as an unbalanced subtree is found and propagate that information upward. So the general optimization pattern is: identify repeated work → see what information the parent actually needs → return that information from recursion → solve multiple things during the same traversal. This changes many tree problems from potentially O(n²) to O(n).
